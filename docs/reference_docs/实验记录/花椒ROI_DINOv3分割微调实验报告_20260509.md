## 1. 目标

本次任务目标是把花椒含油率检测流程中的 ROI 提取从传统图像处理方法升级为可训练的分割模型：

- 输入：1 张 RGB 图片。
- 输出：花椒 ROI 二值 mask、coverage、可选 mask/overlay 调试文件。
- 模型：使用 `/home/yr/yr/code/cv/large_models/dinov3_all` 中的 DINOv3 代码和 `models` 中的本地权重。
- 显存约束：选择 24G 显卡可运行的模型。
- 训练数据：当前手工标注的花椒 ROI 数据。
- 划分：严格沿用当前含油率检测的 train/val split，不重新随机划分。
- 最终用途：输出的 ROI mask 后续用于同视角、同尺寸的高光谱 cube 聚合光谱，再输入含油率模型。

## 3. 模型选择

已检查 DINOv3 本地模型与权重：

- 选定模型：`dinov3_vits16`。
- 选定权重：`/home/yr/yr/code/cv/large_models/dinov3_all/models/dinov3/dinov3_vits16_pretrain_lvd1689m-08c60483.pth`。
- 权重大小：约 83MB。
- Backbone 参数量：约 21.6M。
- 224 输入 smoke 输出：patch tokens shape `(1, 196, 384)`。
- 本机 GPU：NVIDIA GeForce RTX 5090 Laptop GPU，显存约 23.42GB。

未选择更大模型的原因：

- `dinov3_vitl16` 权重约 1.2G，训练/推理显存和耗时更高，小样本 ROI 任务收益不确定。
- `dinov3_vith16plus` 权重约 3.2G。
- `dinov3_vit7b16` 权重约 4.1G，且 7B backbone 不适合当前 24G 单卡快速微调展示。

最终结构：

- DINOv3 ViT-S/16 frozen backbone。
- 使用 `forward_features()` 提取 `x_norm_patchtokens`。
- patch tokens reshape 为 feature map。
- 添加轻量二值分割 head：Conv 3x3 + GroupNorm + ReLU + Dropout2d + Conv 1x1 + bilinear upsample。
- 输出 1 通道 ROI logits，再 sigmoid + threshold=0.5 得到 mask。

## 5. 训练配置

正式训练命令：

```bash
PYTHONPATH=src /home/yr/anaconda3/envs/hj/bin/python scripts/train_dinov3_roi_segmentation.py \
  --epochs 20 \
  --batch-size 4 \
  --image-size 448 \
  --lr 1e-3 \
  --weight-decay 1e-4 \
  --head-channels 128 \
  --dropout 0.1 \
  --out-dir artifacts/huajiao-dinov3-roi-seg-v0.1.0 \
  --num-workers 0 \
  --device cuda \
  --amp \
  --freeze-backbone
```

训练策略：

- Backbone 冻结，只训练轻量分割 head。
- 输入 resize 到 448x448。
- Loss：0.5 * BCEWithLogitsLoss + 0.5 * Dice loss。
- Optimizer：AdamW。
- AMP：启用 CUDA autocast。
- 每个 epoch 在 val split 上评估 Dice/IoU/Precision/Recall/Accuracy。
- 以 val Dice 选择 best checkpoint。

## 12. 安全加载与交付加固

独立代码审查指出：PyTorch checkpoint 采用 pickle 反序列化机制，若加载不可信 artifact 或不可信 backbone 权重，存在 unsafe deserialization 风险。已完成以下加固：

- `DinoV3ROIPredictor.from_artifact()` 在加载 `best_model.pt` 前读取 `manifest.json` 并校验 `best_model_sha256`。
- 同时根据 `config.json` / `manifest.json` 校验 DINOv3 backbone 权重 sha256。
- sha256 不一致或 manifest 缺失时直接拒绝加载。
- 分割头 checkpoint 加载改为 `torch.load(..., weights_only=True)`。
- 新增单元测试覆盖 checkpoint 被篡改和 backbone 权重被篡改两类失败路径。

部署约束：应用服务只应加载内部生成并保留 manifest/hash 的可信 artifact，不能把用户上传的任意 `.pt/.pth` 文件作为模型加载。

## 13. 风险与后续建议

1. 小样本风险：只有 197 张手工标注，尽管 train/val 指标接近，仍建议使用外部 11 张 `huajiao_test` 或新采集样本做独立测试。
2. 标注口径风险：当前模型学习的是粗 polygon ROI，而不是精细花椒颗粒 mask。若应用展示要求“只框出花椒颗粒，不含背景纸/托盘”，需要重新定义并补充精细分割标注。
3. 下游含油率风险：DINOv3 ROI mask 的 coverage 约 0.44，与历史 refined 光谱 coverage 约 0.17 不同。必须用 DINOv3 mask 重新从 cube 提取 train/val 光谱并重训含油率回归模型，不能直接把旧含油率模型指标视为部署指标。
4. 部署权重风险：artifact 默认不复制 83MB DINOv3 backbone 权重；公司服务器部署时需同步权重路径，或修改 artifact 发布流程把 backbone 权重纳入内部对象存储/Git LFS。
5. 性能建议：当前单图推理可用于展示。若应用端并发较高，建议服务启动时常驻加载 `DinoV3ROIPredictor`，不要每次请求重新加载模型。
